# 最近五季財報與日期一致性：完整調整方案

狀態：待實施的方案。日期：2026-10-22。適用：Earning Tracker 全部公司。本文不代表網站已修改。

## 1. 調整目的

每家公司維持最新五個「已公布季度」的有效紀錄，最新在前；新季度經官方來源確認入庫時，才移除有效清單中最舊的一季。同時清楚區分公司財年、季度涵蓋期間、公布日期、SEC 申報日期及下一次業績事件，統一季度財務數值口徑。

「每家公司五份」定義為五個不同季度，不是五份不同 SEC 文件。10-Q、10-Q/A、8-K、業績公告、10-K 都可能對應同一季度，不能重複佔位。已有至少五個可信季度者必須保留五季；不足五季者顯示實有數量及缺漏狀態，不捏造資料補滿。

有效歷史資料檔及網站都必須最多五季，不能僅在畫面隱藏第六張卡片。被移除的資料可透過 Git 修訂紀錄回復，不在網站另行展示額外季度。

## 3. 顯示規則

歷史卡片標題改為 `FY2027 Q2（公司財年）`；另列「季度截止日」與「財報公布日」。不以公布年份重新命名公司季度；如需要按公布年搜尋，可增加獨立日期篩選，不混入財年標籤。

目前標為 `2026 FY`、營收卻為單季數字的卡片，核實期間後改為 `FY2026 Q4`。10-K 保留為「來源文件：10-K 年報」，不把年度文件種類當作全年業績期間。全年數值不佔五季名額，也不與 Q4 單季數值混用。

各卡片固定展示季度營收及 GAAP 稀釋 EPS。調整後 EPS 如需要保留，必須有獨立欄位及 non-GAAP 標籤；第一版不將兩種 EPS 放在同一比較序列。FY2027 Q1 截圖中的 $1.87 是 non-GAAP；同季官方 GAAP 為 $2.39，需重新核對舊卡片。FY2027 Q2 官方 GAAP 為 $2.46。

官方公告已發布但 SEC 10-Q 未取得時，卡片仍可顯示已確認季度及公布日，附官方公告連結；SEC 按鈕明確顯示「10-Q 連結待取得」，不能把缺少 SEC 連結誤認為尚未發布財報。

公司主列分開顯示「最新已公布季度」與「下一次預定業績事件」。尚未確認下一次日期時顯示「尚未公告下次日期」；不可繼續把剛過去的日期當作下次日期，也不可自行加三個月。

## 4. 資料模型及一致性

新增或正規化以下欄位；現有格式應先保留相容讀取，統一寫入後再移除舊字串依賴：

| 類別 | 欄位及規則 |
|---|---|
| 公司身份 | CIK／公司識別碼；ticker 是映射而非唯一發行人身份。GOOG、GOOGL 可共享同一官方來源。 |
| 季度身份 | fiscalYear、fiscalQuarter、periodStart、periodEnd、periodScope=quarter；唯一鍵以公司身份與已核實的季度期間構成。 |
| 日期 | releaseDate、filingDate、callAt 分開；保留公布時間與原時區（來源提供時）。美東日曆用於美股日期及倒數。 |
| 數值 | revenue、currency、epsGaapDiluted、epsBasis、periodScope；明確區分單季、年初至今與全年。 |
| 來源 | releaseSourceUrl、metricSourceUrl、SEC accession／secUrl、verifiedAt；按日期、季度及每個數值保存核實狀態。 |
| 未來事件 | expectedReleaseDate、scheduledCallAt、eventType、source、sourceUrl、checkedAt，與已公布歷史分開。 |

同一季度的不同文件合併到同一筆紀錄。修訂文件或重述覆蓋該季度相關欄位，保存來源版本，不新增第六筆，也不把修訂公布日當作新的季度。公司變更財年、52／53 週財年及過渡期須依官方期間處理，不能只用月份或固定天數推算。

EPS 不以全年 EPS 減前三季 EPS 推算 Q4。累計營收轉單季只有在期間、幣別及會計口徑一致且保留推導來源時才可採用；預設優先使用官方明示的單季數值。找不到可靠數字時顯示待補。

## 5. 自動更新與五季保留

流程為：發現官方事件 → 取得官方來源 → 確認季度身份及公布日 → 解析並核實欄位 → 合併同季紀錄 → 選出最新五季 → 驗證 → 一次發布。

1. **發現。** 每日覆蓋所有代碼，包括日期空白、日期已過期及來源曾失敗者；發報窗口內的公司每小時檢查。第三方只能發現候選，不能充當已公布的唯一證據。
2. **來源。** 公司 IR 公告、RSS／日程與 SEC 8-K 的 Item 2.02／Exhibit 99.1 用於發現業績；10-Q／10-K 補充期間、GAAP 數字及原文連結。不同公司需可維護的來源對應及解析器，不假設一個通用解析器能可靠處理全部公司。
3. **最低入庫條件。** 已有可追溯的官方公布證據、已確認季度身份與期間、實際公布日不在未來，才可成為新歷史。數字可個別待補；尚未核實的 EPS／營收顯示空值，不阻止已確認的公布事實及季度顯示。
4. **合併去重。** 同一期公告、8-K、10-Q、修訂版只更新同一筆；重跑不增加紀錄，也不反覆淘汰舊季。
5. **排序。** 按已核實的季度期間由新至舊排序。公布日用於展示及合理性檢查；不按字串、抓取時間或修訂文件日期決定最新季度。
6. **裁切。** 每次成功更新後，正式有效歷史檔每家公司最多五個季度，前端另作排序及五筆上限防護。裁切發生在合併和驗證之後。
7. **防止舊資料復活。** `official_history.json` 等舊輸入再次套用時，不重新加入已退出窗口的季度。所有資料寫入路徑共用同一保留規則，而非只修前端或單一腳本。
8. **發布。** 在暫存區生成並完整驗證資料檔與狀態檔，以同一 Git commit 作為發布單位；任何必要檢查失敗時不發布該批損壞結果。原子更換單一檔案本身不等於多檔交易。

## 6. 失敗處理、排程及成本

- 抓取或解析失敗：保留既有五季，不先刪舊季；標記本次失敗及最近成功時間，保留待重試候選。
- SEC 不可用但公司公告可用：已確認的公告及季度可入庫；SEC 連結獨立等待，不把系統設計成必須等 10-Q 才承認業績發布。
- 新季度只有第三方訊號：維持候選狀態，不佔五季名額，不淘汰正式歷史。
- 來源衝突或不支援的特殊報表：進入例外清單，保留原紀錄及明確待核實狀態。自動化不能保證所有官方網頁格式永遠可解析。
- 先修復 SEC 代理網址格式，增加 URL 驗證、請求預檢和分來源結果；SEC 全部失敗時不能再呈現整體資料健康成功。有效 Yahoo 更新可保留，但必須如實標示官方資料服務異常。
- 每小時窗口檢查、每日全市場巡檢；採快取、來源變更檢測及按 CIK 去重，避免每小時完整下載 503 家財報。既有定時工作需監測建立時間與資料完成時間；若依賴外部排程，使用獨立的資料更新觸發器，不改動 Bark 通知排程。
- 「每小時檢查」是檢查頻率，不保證官方公布後零延遲。可量測的目標為：來源可取得且解析成功後，在一個更新週期內入庫；對不支援來源與平台排程失敗另列異常。維護公司來源解析器是主要持續成本；付費日曆／數據供應商可減少維護，但不能省略財年與期間核對。

## 7. 現有資料遷移

先從最新遠端版本建立獨立工作副本並保存目前資料快照，避免使用落後的本機主目錄覆蓋線上程式。

1. 盤點所有公司的紀錄數、重複季度、FY／Q4 混用、缺期間及 EPS 口徑。
2. 先以 NVIDIA 建立完整五季的官方核對示範，驗證標籤、期間及 GAAP 數值。
3. 對全部公司依同樣規則補核實；能取得五季者保留五季。無法核實的舊紀錄可暫保留於原有五筆窗口並明示未核實，數值不得冒充已核實；不足五季者顯示實有資料及原因。
4. 正規化後統一去重、排序及裁切。輸出遷移前後差異，特別列出將退出有效窗口、被更正數值與仍待核實的紀錄。
5. 完成測試與網站桌面／手機驗收後，先發布可回復的資料與顯示調整，再啟用持續官方更新，核對至少兩次排程執行。

## 8. 建議修改範圍

- `verified_history.py`：季度身份、同季合併、欄位核實狀態與統一保留五季規則。
- 新增小型官方來源模組及來源設定：發現候選、擷取公告及解析，不把公司特殊解析堆入既有大型更新腳本。
- `update_data.py`：官方連線預檢、缺日期覆蓋、估計值期間核對；移除以不明期間欄位冒充下一季預估的行為。
- `historical_data.json`／`official_history.json`：遷移及避免舊資料重放；狀態檔另分最新已發現季度與最新已發布季度。
- `index.html`／`i18n.mjs`：最新在前、五季上限、財年說明、公布日／截止日、來源與資料健康狀態。
- `.github/workflows/main.yml`：分來源健康檢查、官方入庫工作、發布驗證及排程延遲觀測；資料寫入工作共用互斥控制。

主列的「預期 EPS $15.91／預估營收 $253.49B」也必須核對預估期間。目前程式直接取 `epsForward` 等欄位，沒有綁定下一次財報季度，不能保證這些數字屬於下一季。缺少明確季度、來源或幣別時先顯示待取得，而不是用不明期間數字補上。若供應商只能提供全年預估，須獨立標示全年口徑。

## 9. 驗收標準

1. NVIDIA 正好顯示上表五季，FY2027 Q2 在第一張；FY2026 Q1 不再出現在正式有效歷史。
2. 所有公司有效紀錄最多五季；有五個可信季度者不因更新程序縮成四季或零季。
3. 新季度官方確認後新增一筆、淘汰最舊一筆；更新失敗或只有預告日期時原清單不變。
4. 同季 8-K、10-Q、修訂版及重跑均不重複計數；修訂舊季度也不把它移到最新位置。
5. FY2026 Q4 保持單季數值，10-K 文件標籤不會把單季誤標全年；GAAP 與 non-GAAP 不混用。
6. 未來公布日不進入歷史；電話會議日、公布日及申報日不互相替代；北京與美東跨日時倒數一致。
7. 公司公告已發布、SEC 連結未取得時能顯示最新已公布季度及公告來源，不長期卡在舊季。
8. 來源失敗、代理格式錯誤、解析衝突及某公司缺資料都留下可定位的狀態，不被成功計數掩蓋。
9. 遷移及兩次連續更新後，舊來源清單不會重新插回已淘汰季度。
10. 桌面與手機最多五張、最新在前；原有搜尋、收藏、語言切換及官方連結仍正常。

以上為方案與驗收要求，尚未修改產品程式、正式資料、部署或憑證。
